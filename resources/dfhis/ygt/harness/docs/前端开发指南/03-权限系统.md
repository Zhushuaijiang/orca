## 权限码来源

权限码存储在主应用菜单树的每个菜单项的 `permissions: string[]` 字段中：

```ts
// 主应用 useMenuStore MenuItem
interface MenuItem {
  id: string;
  title: string;
  path: string;
  icon?: string;
  permissions?: string[];  // ← 权限码在这里
  children?: MenuItem[];
}
```

主应用 `checkPermission(code)` 遍历 `flatMenus` 查找匹配。

## 子应用三层权限消费

### 1. 路由级权限

```ts
// 子应用 src/router/index.ts
{
  path: '/admin',
  meta: {
    title: '管理页面',
    permission: '{module}:admin:view',  // 需要的权限码
  },
}
```

守卫行为（`src/router/guards.ts`）：
- 无权限 → 阻止导航
- 有来源页 → `next(false)`
- 无来源页 → `next('/')`
- 显示 "无权限访问该页面" 通知

### 2. 元素级权限 — v-permission 指令

```vue
<!-- 单个权限码 -->
<button v-permission="'{module}:patient:add'">新增</button>

<!-- 多个权限码（任一匹配即显示） -->
<button v-permission="['{module}:patient:edit', '{module}:patient:delete']">操作</button>
```

实现差异：

| 实现 | 无权限行为 | 来源 |
|------|-----------|------|
| 子应用 | `display: none` + `data-no-permission` | `directives/permission.ts` |
| 主应用 | `removeChild` 移除 DOM | `shared/permission.ts` |

### 3. 编程式权限 — usePermission

```ts
import { usePermission } from '@/composables/usePermission';

const {
  checkPermission,     // (code: string) → boolean
  hasAllPermissions,   // (...codes: string[]) → boolean
  hasAnyPermission,    // (...codes: string[]) → boolean
  hasRole,             // (...roles: string[]) → boolean
} = usePermission();

if (checkPermission('{module}:patient:add')) { /* 有新增权限 */ }
if (hasAllPermissions('code1', 'code2')) { /* 同时拥有两个 */ }
if (hasAnyPermission('code1', 'code2')) { /* 至少一个 */ }
if (hasRole('admin')) { /* 是管理员 */ }
```

独立模式下所有方法返回 `true`（全部放行）。

## DfButton 的两条显隐链路

当前主应用中的 `DfButton` 有两条并行机制：

### 1. 显式 `perm` 模式

适用于仍然由后端权限码控制的业务按钮：

```vue
<DfButton text="删除" perm="system:user:delete" />
```

- 这条链路仍走 `@df/ui` 的权限能力。
- `configureDfUi({ defaultPermMode: 'hide' })` 会在无权限时将按钮从 DOM 中移除。

### 2. `finalCode` 显隐覆盖模式（主应用专属）

适用于当前主应用的调试/治理场景：

- 每个 `DfButton` 都会注册 `finalCode`
- `useButtonVisibilityStore` 以 `finalCode` 为 key 持久化覆盖值
- `setupButtonVisibilitySync(router)` 监听 store、路由切换和 DOM 变化，将覆盖值同步到真实按钮 DOM
- 管理入口：`/system/devtools/button-codes`

这个模式不替代后端权限，而是补充了“按按钮实例显隐”的治理能力，尤其适合联调阶段核对按钮注册、消歧结果和页面上的最终可见状态。


## 主应用路由守卫流程

完整流程（`src/auth/guards.ts`）：

```
1. NProgress.start()
2. 白名单路径（/login, /404, /403）→ 直接放行
3. 已登录 + 访问 /login → 重定向首页
4. 无 token → 重定向 /login
5. Token 过期 → 清除状态 → 重定向 /login?expired=1
6. 有用户信息 → hasPathAccess() 检查 → 不通过 → /403
7. 无用户信息（刷新）→ loadUserData() 加载用户/租户/菜单/字典/路由
```
