# 10 - 登录认证与会话

## 概览

主应用负责完整的认证流程：登录、Token 管理、路由守卫、会话监控。子应用不参与认证逻辑，直接消费主应用传递的登录状态。

## 认证架构

```
用户 → 登录页 (/login)
         │
         ▼
    useAuth().login(params)
         │
    ┌────┴────┐
     │ DEV/devDebug │ → createDevToken() → mock 身份 + 真实菜单接口
     │ 生产模式     │ → POST /auth/login → 保存 token → 加载数据
    └────┬────┘
         │
         ▼
    setupGuards(router)
         │
         ▼
    beforeEach 守卫 → 7 步验证流程
```

## Token 管理

### 存储

```ts
sessionStorage.setItem('df_access_token', accessToken);
sessionStorage.setItem('df_refresh_token', refreshToken);
```

### Token 工具函数（`src/auth/token.ts`）

| 函数 | 说明 |
|------|------|
| `getToken()` | 获取 access token |
| `setToken(token)` | 保存 access token |
| `getRefreshToken()` | 获取 refresh token |
| `setRefreshToken(token)` | 保存 refresh token |
| `clearTokens()` | 清除所有 token |
| `isTokenExpired(token)` | 检查 token 是否过期（解析 JWT payload） |
| `getTokenExpireAt(token)` | 获取过期时间戳 |
| `createDevToken()` | DEV 模式 mock JWT（有效期 1 年） |

### Token 刷新队列（`src/api/request.ts`）

```
请求 A → 401 → 触发 refresh（首个）
请求 B → 401 → 排队等待
请求 C → 401 → 排队等待
refresh 成功 → A/B/C 全部用新 token 重发
refresh 失败 → 清除状态，全部跳转 /login
```

DEV 模式下 401 直接清理状态跳登录（无刷新）。

## 登录流程（`src/auth/useAuth.ts`）

### DEV / devDebug 模式

```
login()
     → createDevToken()
     → mock 用户/租户
     → fetchMenus()（真实接口，失败回退本地快照）
     → reconcileLocalNavigationState()
     → syncDynamicRoutes()
     → setWatermark()
     → startSessionMonitoring()
     → connectWebSocket()
```

### 生产模式

```
login(params)
     → POST /auth/login { username, password }
     → 保存 accessToken + refreshToken
     → 响应内 user → useUserStore
     → 响应内 tenant → useTenantStore
     → 并行加载 fetchMenus() + fetchDicts()
  → setWatermark(realName)
  → startSessionMonitoring()
  → connectWebSocket()
  → router.push(redirect || '/')
```

## 登出流程

```
logout()
     → clearTokens()
  → 清理所有 Store 状态
  → clearWatermark()
  → disconnectWebSocket()
  → stopSessionMonitoring()
  → clearTransientShellState()
     → resetRouter()
     → eventBus.emit('logout')
     → （生产环境）fire-and-forget POST /auth/logout
```

## 路由守卫（`src/auth/guards.ts`）

### beforeEach 7 步流程

```
1. NProgress.start()
2. DEV 下 `/system/devtools/button-codes?mockButtons=N` 直接放行
3. 白名单路径（/login, /404, /403）→ 直接放行
4. 已登录 + 访问 /login → 重定向首页
5. 无 token → 重定向 /login
6. Token 过期 → 清除状态 → 重定向 /login?expired=1
7. 有用户信息 → hasPathAccess() 检查 → 不通过 → /403
8. 无用户信息（页面刷新）→ loadUserData() 加载用户/菜单/字典/路由
```

### afterEach

- 埋点追踪路由变化
- 关闭 NProgress

## 会话监控（`useSessionStore`）

- 监听鼠标移动、键盘输入、点击等用户活动
- 超时无活动自动登出
- 支持会话续期（`renewSession`）
- 超时阈值可配置

## API 请求拦截（`src/api/request.ts`）

### onRequest

```ts
headers.set('Authorization', `Bearer ${getToken()}`);
headers.set('X-Trace-Id', generateTraceId());
```

### onResponseError

| 状态码 | 行为 |
|--------|------|
| 401 | `devDebug` 直跳登录，其余环境走 Token 刷新队列 |
| 403 | 跳转 `/403` |
| 其他 | 抛出错误 |

## 子应用如何感知认证状态

子应用不需要处理认证，但可以通过以下方式感知：

```ts
// 获取当前用户
const { store } = useMainApp();
const userName = store?.user?.realName;

// 监听登出事件
const { eventBus } = useMainApp();
eventBus?.on('logout', () => { /* 清理子应用状态 */ });
```

## 独立链接与单点登录

需要从已登录的主应用或子应用打开同源独立页面时，不要复制父窗口的 `sessionStorage`。正确流程是：当前窗口调用主应用 `/api/df-ygt-main/sso/getCode` 获取一次性 `appCode`，把 `appCode` 追加到目标 URL；新窗口路由守卫在无 token 时消费 `appCode`，通过 `/api/df-ygt-main/sso/doLogin` 换取当前用户授权后继续加载菜单和目标页面。消费成功后守卫会从地址栏移除 `appCode`。

如果第三方只能配置一个独立链接，也可以在 URL 上携带 OAuth2 客户端凭证。患者 360 这类无需主应用壳的页面使用主应用 SSO 守卫换取访问令牌，守卫成功后会清理地址栏里的凭证参数，并保留 `standalone=patient360` 让布局进入无壳模式：

```text
http://192.168.199.41:8001/biz-zhusuoyin/patient360/patient/{patientId}?sourcePreference=patient360-database&ssoClientId={clientId}&ssoClientSecret={clientSecret}
```

兼容参数名：`clientId` / `clientSecret`。可选参数：`ssoScope`。该模式会隐藏主应用顶部栏、左侧菜单和标签页，只保留患者 360 页面本体。
