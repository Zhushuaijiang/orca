### MicroApp 类型

```ts
interface MicroApp {
  name: string;
  entry: string;
  defaultEntry: string;
  activeRule: string;
  container: string;
  title: string;
  timeoutMs: number;
  capabilityVersion: string;
  prefetch: 'critical' | 'minor';
  healthCheckPath?: string;
  mode: 'route' | 'silent';
  providerModulePath?: string;
}
```

### 路径匹配

- `getMicroAppByPath(path)` — 按 activeRule 前缀匹配，长规则优先
- `isMicroAppPath(path)` — 判断路径是否属于某个子应用
- `getMicroAppScope(app)` — 从 activeRule 提取作用域名

## 加载状态机（`src/micro/loader.ts`）

### 状态流转

```
idle → loading → ready → mounted
                ↘ error
                ↘ timeout
```

### 状态变量

| 变量 | 类型 | 说明 |
|------|------|------|
| `loadingApp` | `Ref<string \| null>` | 当前正在加载的子应用名 |
| `activeMicroApp` | `Ref<string \| null>` | 当前已挂载的子应用名 |
| `errorApp` | `Ref<MicroLoadErrorState \| null>` | 加载出错的子应用 |
| `microStates` | `Ref<Record<string, MicroRuntimeState>>` | 所有子应用运行时状态 |

### 超时机制

- 每个子应用默认 15 秒加载超时
- 加载超过 3 秒触发 `micro_load_slow` 告警埋点
- 超时自动标记为 `timeout` 状态

### 静默子应用探测

`common-biz` 是 silent 模式，不参与路由渲染。主应用通过 `prefetchSilentMicroApps()` 主动探测：

1. HTTP HEAD 健康检查（`healthCheckPath`）
2. 动态 import provider 模块验证可用性
3. 探测结果标记 `ready` 或 `error`

## 生命周期（`src/micro/lifecycle.ts`）

### qiankun 全局钩子

```
beforeLoad(app)  → 埋点 track('load_start')
beforeMount(app) → 无特殊处理

```

## 注册与启动（`src/micro/register.ts`）

### setupMicro()

```ts
function setupMicro() {
  // 1. 初始化所有子应用运行时状态
  registerMicroAppsState(microApps);

  // 2. 注册路由型子应用到 qiankun
  registerMicroApps(toQiankunApps(routeMicroApps));

  // 3. 全局错误捕获器（归因到具体子应用）
  addGlobalUncaughtErrorHandler(handleGlobalError);

  // 4. 启动 qiankun
  start({
    sandbox: { experimentalStyleIsolation: true },
    prefetch: 'all',
  });

  // 5. 预取静默子应用
  prefetchSilentMicroApps();
}
```

### 全局错误归因

`addGlobalUncaughtErrorHandler` 捕获未处理异常，通过匹配 entry URL 签名归因到具体子应用，避免一个子应用的崩溃影响其他子应用。

### prefetch 策略

| 级别 | 说明 |
|------|------|
| `critical` | 高优先级预取（首屏需要的子应用） |
| `minor` | 低优先级预取（非首屏子应用） |

## 调试系统（`src/micro/debug.ts`）

### 核心函数

| 函数 | 说明 |
|------|------|
| `resolveMicroAppEntry(name, defaultEntry)` | 解析最终入口（考虑调试覆盖） |

### 使用方式

```js
// 主应用控制台
sessionStorage.setItem('devDebug', 'test');
sessionStorage.setItem('df-web-ygt-biz-huanzhe360', 'http://localhost:8106');
// 刷新页面后，主应用将使用 http://localhost:8106 作为该子应用入口
```

### 按钮 code 调试页

主应用提供一个专门的按钮注册调试入口：

```text
/system/devtools/button-codes?mockButtons=200
```

行为说明：

- 仅开发环境可用
- 路由守卫会对该地址做一次性放行，避免依赖登录态
- 页面会生成模拟 `DfButton` 注册数据，便于检查 `finalCode`、消歧结果、显隐覆盖和导出 JSON

### URL 安全

`normalizeMicroAppEntry` 拒绝 `javascript:` 和 `data:` 协议，防止 XSS。

## MicroContainer 渲染

`MicroContainer.vue` 消费 loader 状态：

```
loadingApp === name → 显示 Loading 动画
errorApp?.name === name → 显示错误信息 + 重试按钮
正常 → 渲染 #micro-container
```
