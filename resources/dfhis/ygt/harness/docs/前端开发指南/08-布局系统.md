# 08 - 布局系统

## 概览

主应用布局由 `MainLayout.vue` 统一管理，包含以下区域：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ HeaderBar — 品牌 + 院区选择 + 搜索 + 消息 + 用户菜单                    │
├──────────┬───────────────────────────────────────────────────────────────┤
│ SideMenu │ TabBar — 可拖拽标签页 + 右键菜单（关闭/关闭其他/关闭所有）      │
│          ├───────────────────────────────────────────────────────────────┤
│ 左侧折叠 │ MicroContainer (#micro-container)                            │
│ 菜单 +   │ ┌───────────────────────────────────────────────────────────┐ │
│ 飞出面板 │ │ 子应用渲染区域                                            │ │
│          │ │                                                           │ │
│          │ └───────────────────────────────────────────────────────────┘ │
│          ├───────────────────────────────────────────────────────────────┤
│          │ SubTabBar — 子应用内子标签（如需）                              │
├──────────┴───────────────────────────────────────────────────────────────┤
│ AppRightDock — 右侧上下文工具栏（可折叠）                                 │
├──────────────────────────────────────────────────────────────────────────┤
│ CommandCenter — 全局命令面板（Ctrl+K）                                    │
│ PreferenceCenter — 偏好设置面板                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

## 核心布局组件

### MainLayout.vue

主布局容器，管理整体布局结构：

- 响应式侧边栏折叠（`useLayoutStore`）
- 标签页路由同步（`useTabStore`）
- 全屏模式切换
- 右侧 Dock 面板状态

### HeaderBar.vue

顶栏组件：

- 品牌 Logo
- 院区选择下拉（`useTenantStore.campusList`，切换触发 `switchCtx` 事件）
- 全局搜索
- 消息通知入口
- 用户菜单（个人信息、修改密码、登出）
- 主题/密度切换

### SideMenu.vue

左侧折叠菜单：

- 折叠状态管理（`useLayoutStore.isCollapsed`）
- 飞出面板（hover 时展开子菜单）
- 收藏菜单（`useFavoritesStore`）
- 菜单数据来自 `useMenuStore.menus`

### TabBar.vue

可拖拽标签页：

- 最多 20 个标签
- 右键菜单：关闭、关闭其他、关闭所有、刷新
- 标签页状态由子应用后置守卫 `eventBus.emit('sub-app:route-change')` 驱动
- 支持拖拽排序
- 状态持久化（`useTabStore`）

### MicroContainer.vue

子应用渲染容器：

- `<div id="micro-container">` 供 qiankun 挂载
- Loading 状态（`loadingApp` ref）
- 错误状态（`errorApp` ref）— 支持重试按钮
- 超时提示

### SubTabBar.vue

子应用内部子标签（可选，供需要二级标签的子应用使用）。

### AppRightDock.vue

右侧上下文工具栏：

- 子应用通过 `actions.setRightDockItems(scope, items)` 注册工具
- 离开子应用时通过 `actions.clearRightDockItems(scope)` 清理

### CommandCenter.vue

全局命令面板（类似 VS Code 的 Ctrl+K）：

- 快速搜索菜单项
- 快速执行操作

### PreferenceCenter.vue

用户偏好设置面板：

- 主题选择
- 密度偏好
- 布局偏好

## 子应用页面与查询栏约束

主应用只负责外壳、页签、微应用挂载边界和主题桥接；子应用页面负责自己的内容区布局。为了避免独立运行和 `8001` 集成运行出现两套效果，主应用 `src/styles/micro-layout-bridge.css` 与各子应用 `src/styles/theme-bridge.css` 必须保持同一套布局语义变量和查询栏规则。

### 页面边距

1. 子应用页面根外框固定为 `0px`，不要在主应用挂载区外再加一圈默认 padding。
2. 页面级查询区、表格区、分栏区、内部主 Tab 的块间距统一使用 `1px` 细分隔；控件内部留白使用 `8px` 内容内边距。
3. 同级区块外沿必须对齐，查询区不能比表格、分栏、编辑器多缩进一层。
4. 页面私有样式只保留业务状态和特殊内容排版，不再散落 `padding: 12px/16px`、`gap: 12px/20px` 这类局部规则。

推荐变量：

```css
:where(#sub-app, .sub-app) {
  --app-page-padding: 0px;
  --app-content-padding: var(--df-micro-page-padding, 8px);
  --app-panel-gap: 1px;
  --app-tab-content-gap: 1px;
  --app-query-keyword-width: 216px;
  --app-query-type-width: 150px;
  --app-query-state-width: 120px;
  --app-query-state-width-sm: 110px;
  --app-query-short-width: 100px;
}
```

### 查询栏按钮顺序

`DfSearchBar mode="inline"` 的视觉顺序固定为：

```
查询字段 -> 查询按钮 -> 新增/编辑/作废/导入/导出/刷新等查询相关按钮
```

约束：

1. 查询按钮使用主色，必须紧跟最后一个查询字段。
2. 查询相关按钮必须紧跟查询按钮，不能单独靠右、两端分布或跨栏漂浮。
3. `.df-search-bar__fields` 不使用 `flex: 1` 填满剩余空间；`.df-search-bar__actions` 不使用 `margin-left: auto`、`justify-content: flex-end`、`space-between`。
4. 能在一行放下时必须一行显示；宽度不足时按字段、查询按钮、后续按钮的顺序自然换行。
5. 紧凑查询条不渲染外置可见 label，控件用 `placeholder` + `aria-label`。

主应用桥接样式需要把 fields 和 actions 纳入同一个横向流：

```css
.sub-app .df-search-bar {
  display: flex;
  flex-wrap: wrap;
  gap: var(--app-space-sm);
}

.sub-app .df-search-bar__fields {
  flex: 0 1 auto;
}

.sub-app .df-search-bar__actions {
  flex: 0 0 auto;
  justify-content: flex-start !important;
  margin-left: 0 !important;
}

.sub-app .df-search-bar__fields,
.sub-app .df-search-bar__actions {
  display: contents;
}
```

每次批量调整布局后，至少检查 `879px / 1092px / 1365px / 1920px` 四档宽度，确认查询字段不被截断、查询按钮不远离字段、按钮不在可容纳时提前换行。

## 管理页布局约束

面向基础字典、参数管理、功能管理、菜单管理、机构管理、科室管理这类后台 CRUD 页面，首屏应直接进入工作区，不再额外堆叠独立的说明 hero 或概览 panel。

统一要求：

1. 页面顶部直接进入查询区、树区、表格区或编辑区。
2. 业务说明收敛到当前工作区标题、副标题、空态提示、字段说明或弹窗说明中，不单独占据一整块首屏面板。
3. 统计数字如果不是当前操作决策的必要信息，不放在页面最上方；确需展示时，放在标题栏右侧、工具区或独立分析页。
4. 管理页首屏优先保证“打开即能查、能选、能编、能存”，避免说明性内容继续下压可操作空间。

建议执行口径：

- CRUD 管理页：顶层即列表、树表或表单。
- 主从管理页：顶层即主对象区 + 明细对象区。
- 树维护页：顶层即树或树表格，不再额外增加概览 hero。
