# 后端开发指南

**动工前必须先读本 README，并按顺序完整学习本目录中的开发指南；未完成学习，不得新建服务、不得开始新模块或新接口开发、不得使用 AI 直接生成业务代码、不得提交代码、不得发起 PR、不得进入联调。**

本目录用于存放可直接交付给下游项目、服务团队、代码评审人员和 AI 辅助开发流程使用的最终规范文档。这里的内容不是讨论稿，而是对服务开发真正具有约束力的输出物。

## 1. 开发准入门禁

以下场景触发强制学习要求：

1. 新服务立项与脚手架接入
2. 新模块开发
3. 新接口开发或接口重构
4. 使用 Copilot、Agent 或其他 AI 辅助生成代码
5. 首次参与本仓库开发或评审

触发后必须先完成：

1. 阅读本 README
2. 按强制顺序学习 01、02、03、04 四篇主规范
3. 确认自己知道每类问题应该去查哪一篇主文档

未完成上述学习前，不得动工。

## 7. 执行原则

1. 本目录只描述当前已确认且允许下游使用的能力，不把规划写成现状。
2. 只要涉及统一响应、异常、ID 生成、DTO 状态跟踪、基础 Repository、TraceId、租户上下文、健康检查与管理端点、优雅停机等基础设施，服务团队必须优先复用脚手架或 Spring Boot 4 基线能力，不得自行平替。
3. 业务服务的自由度只存在于业务领域实现，不存在于脚手架级基类、协议和公共基础设施设计。
4. 租户字段统一口径只有一条：数据库 DDL 必须保留 `tenantid not null default '0'`，但业务实体不显式声明 `tenantId`，业务代码不手工 get / set。
5. 架构评审、代码评审、AI 生成结果验收时，应优先使用本目录中的主规范作为依据。

## 8. 维护原则

1. 规范或脚手架能力变更时，必须同步更新对应主文档和本 README。
2. 不得出现代码已变更、文档仍描述旧结构或旧口径的情况。
3. 不得把规划能力、候选方案、示例写法写成当前主规范。
4. 若未完成本 README 要求的学习流程即直接开工，视为开发准入不合格。

## 9. 综合执行清单

以下清单用于替代旧版“服务开发约束清单”的一页式执行入口；遇到详细规则时，仍回到对应主文档查看正文。

### 9.1 立项与接入前

1. 是否已完整阅读 README 与 01-04 四篇主规范。
2. 是否明确新服务应继承 df-parent 还是导入 BOM。
3. 是否明确所需 starter 最小组合，而不是准备全量引入。
4. 是否明确本服务走 Nacos 分层配置，并知道 application.yml 只保留什么。

### 9.2 开发中

1. 是否复用了 R<T>、BusinessException、CommonErrorCode、DTOBase、SequenceUtil、BaseEntity、BaseRepository、RequestContextHolder、JwtTokenService、RedisLockUtil、MessagePublishTemplate、@DfMessageRouteKeyListener、@DS 等既有能力。
2. 是否没有在业务模块新建第二套响应壳、异常壳、错误码、上下文对象、DTO 基类、ID 生成器、公共基础设施层。
3. 实体字段是否补齐中文注释，命名是否符合拼音驼峰规则。
4. 接口是否遵守 GET/POST 约束，是否补齐 OpenAPI 注解与字段级 Schema 描述。

### 9.3 提交 PR 前

1. 是否没有提交 target、日志、生成物、临时调试文件。
2. 是否没有在子模块自行声明第三方依赖版本。
3. 是否同步更新了 README、主规范或相关架构说明。
4. 是否明确区分了“当前已实现”和“后续规划”。

### 9.4 联调与验收前

1. 是否至少跑通一条成功链路。
2. 是否至少跑通一条参数校验失败链路。
3. 是否至少跑通一条业务异常链路。
4. 是否已确认接口、异常、配置、日志、租户、Trace、消息、数据访问入口均遵循主规范。

1. 请通过会话窗口对ai说“

   2、我现在要开发医共体患者360后端微服务，请帮我领域模型目录架构搭出来，方便我直接开始接口设计。”
