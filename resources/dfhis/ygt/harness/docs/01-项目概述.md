# 01 - 项目概述

## 1. 项目名称

**df-ygt-main** —— 医共体（医疗共同体）一体化平台。

## 2. 项目简介

`df-ygt-main` 是面向区域医疗共同体场景的一体化业务平台仓库，承担「**前端微应用 Shell + 后端业务微服务集群**」的整体载体。一期目标是把医共体内的机构、人员、患者、组织协同等核心能力以统一入口对外提供，并在统一的认证、租户、链路、消息、数据访问规范下推进各业务子域的并行开发。

设计原则：

1. **统一底座**：所有后端微服务必须接入 `df-java-base` 脚手架，统一响应 / 异常 / 错误码 / TraceId / 租户 / JPA / Redis / 消息 / JWT 等基础能力，业务模块不重造基础设施。
2. **统一前端 Shell**：基于 qiankun 微前端方案，由 `df-web-ygt-main` 作为主应用容器，业务子前端以微应用形式接入。
3. **领域分治**：主应用承担认证与聚合展现，业务领域（患者 360、机构、处方等）由独立后端微服务承载。
4. **配置中心化**：所有运行配置走 Nacos 分层方案，本地代码仓库不保存敏感连接信息。
5. **规范先行**：开发准入、接口风格、AI 协作、代码评审统一遵循 [docs/后端开发指南/](后端开发指南/README.md) 四篇主规范，规范与代码必须同步演进。

## 3. 技术栈

### 3.1 前端

- **核心框架**：Vue 3.5 + TypeScript 5.7 + Vite 6
- **状态与路由**：Pinia 3 / vue-router 4
- **UI 组件**：DevExtreme 25.2 + 自研 `@df/ui`
- **微前端**：qiankun 2.10
- **运行时通信**：mitt 事件总线 + `@preact/signals-core`

### 3.2 后端

- **语言与运行时**：Java 25（固定 JDK 路径 `D:\Program Files\Java\jdk-25.0.2.10-hotspot`）
- **框架基线**：Spring Boot 4.0.5 / Spring Cloud 2025.1.1
- **统一脚手架**：`df-java-base` 4.0.0-SNAPSHOT（`df-parent` + 各 `df-*-starter`）
- **核心能力来源**：
  - `df-core-starter`：统一响应 `R<T>`、`BusinessException`、`CommonErrorCode`、TraceId、`RequestContextHolder`、`JwtTokenService`、OpenAPI
  - `df-jpa-starter`：`BaseEntity` / `BaseRepository` / 大结果集保护
  - `df-cloud-starter`：Nacos 配置、`@LoadBalanced RestClient`、TraceId 透传
  - `df-tenant-starter`：多租户上下文（一期不强隔离）
  - `df-redis-starter`：`RedisLockUtil` / `RedisUtil`
  - `df-message-starter`：`MessagePublishTemplate` / `@DfMessageRouteKeyListener`

### 3.3 中间件

- **数据库**：MySQL（连接信息走 Nacos `df-ygt-biz-{服务名}.yaml`）
- **缓存**：Redis（共享配置 `df-shared-infra.yaml`）
- **消息**：RabbitMQ（共享配置 `df-shared-infra.yaml`，开启 lazy queue / operator-policy 队列治理）
- **配置中心 / 注册中心**：Nacos（分层 DataId）
- **检索（按需）**：Elasticsearch

## 5. 后端服务划分

| 服务名 | 职责 | 状态 |
|--------|------|------|
| `df-ygt-main` | 主应用：OAuth2 认证、用户主体、角色权限、菜单、租户、门户聚合 | 骨架已搭建，接口待设计 |
| `df-ygt-biz-*`（其他领域服务） | 患者、机构、处方、协同等具体业务领域 | 规划中，按子域陆续接入 |

> 主应用**不**承载具体业务领域；患者 360、机构管理、处方流转等能力由独立子服务承载，主应用通过聚合调用对前端 Shell 暴露统一入口。

## 6. 主应用 (df-ygt-main) 领域划分

| 子域 | 职责 |
|------|------|
| `apis` | 跨服务远程调用契约定义，统一维护基于 `@HttpExchange` 的接口与共享请求/响应 DTO；provider 不要求 implements，consumer 通过自动配置直接注入代理 |
| `domain/auth` | OAuth2 认证：登录、token 颁发与校验、客户端管理（token 复用 `JwtTokenService`） |
| `domain/user` | 用户主体映射、当前用户、个人中心 |
| `domain/permission` | 角色 / 权限 / 菜单 / 资源治理 |
| `domain/tenant` | 租户基础治理（一期保留 `tenantid` 不强隔离） |
| `domain/portal` | 门户聚合：工作台、应用入口、跨域待办与消息汇总 |

代码统一五件套：`controller/`、`service/`、`model/`、`repository/`、`dto/`。详见 [backend/README.md](../backend/README.md)。

## 7. 前端 Shell (df-web-ygt-main) 能力概览

主前端 Shell 一期已落地的能力（详见 `frontend/df-web-ygt-main/src/`）：

- **微前端容器**：qiankun 注册、生命周期、共享上下文（`micro/`）
- **认证与会话**：登录、token、路由守卫（`auth/`）
- **布局体系**：`MainLayout` + 顶栏 / 侧栏 / 标签页 / 子标签 / 右侧 Dock / 命令中心 / 面包屑（`layout/`）
- **消息中心**：STOMP 客户端、待办、消息中心（`message/`）
- **可观测性**：TraceId、错误处理、调试面板、健康检查、埋点（`monitor/`）
- **路由体系**：静态路由 + 动态路由（`router/`）
- **状态管理**：Pinia stores（菜单 / 偏好 / 主题 / 租户 / 用户 / 标签 / 收藏 / 字典 / 会话 / 布局 / Dock / Shell UI）
- **共享能力**：对话框、主题、事件总线、应用打开、权限、Toast、水印（`shared/`）

## 9. 快速开始

### 9.1 环境要求

| 组件 | 版本 |
|------|------|
| JDK | 25（路径 `D:\Program Files\Java\jdk-25.0.2.10-hotspot`） |
| Maven | 3.9+ |
| Node.js | 20+ |
| pnpm | 9+ |
| MySQL | 8.x |
| Redis | 7.x |
| RabbitMQ | 3.12+ |
| Nacos | 2.x |

### 9.2 后端启动（以主应用为例）

```powershell
. .\scripts\harness\ygt-env.company-dev.ps1

cd backend
mvn spring-boot:run "-Dspring-boot.run.arguments=$env:YGT_LOCAL_BACKEND_RUN_ARGS"
```

启动前提：

1. Nacos 中已上传 `df-shared-infra.yaml` 与 `df-ygt-main.yaml`（参考仓库内 `nacos-examples/`）。
2. MySQL / Redis 已就绪并与 Nacos 配置中的连接信息一致。

### 9.3 前端启动

```powershell
cd frontend\df-web-ygt-main
pnpm install
pnpm dev
```

### 9.4 联调与验收最低要求

推荐使用 harness 做最小闭环：

```powershell
node scripts/harness/ygt-workflow.mjs impact --project main --json
node scripts/harness/ygt-workflow.mjs verify --project main --profile standard --changed-only
node scripts/harness/ygt-workflow.mjs review --project main --json
```

按 [04-AI协作与代码评审规范.md](后端开发指南/04-AI协作与代码评审规范.md) §7.1，每个新接口至少跑通：

1. 一条成功链路
2. 一条参数校验失败链路
3. 一条业务异常链路
