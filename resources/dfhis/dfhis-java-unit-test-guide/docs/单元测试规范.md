# Java 后端单元测试指南

适用于 Java/Spring 后端服务。默认基线：Java 8、Spring Boot 2.2.x、Gradle、JUnit 4、Mockito。

> 配套技能包：dfhis-java-unit-test-guide（精简门禁 + 落地流程）。本文为完整规范。

## 1. 依赖

在**实际业务模块**的 `build.gradle` 中检查 `dftest-spring-boot-starter`，不能只检查根项目。

没有有效（未注释）的 `dftest` 依赖时，必须先添加：

```gradle
dependencies {
    testCompile 'com.df.cbhis:dftest-spring-boot-starter:<版本>'
}
```

版本按同服务、同 Spring Boot/Starter 基线选择：

- 已统一采用新版 starter 的服务使用 `2.0.0-SNAPSHOT`。
- 同一模块只保留一个 `dftest` 版本，不按"最新"随意升级。
- 旧模块沿用 `testCompile`；已迁移模块沿用 `testImplementation`。

JUnit/Mock 参考当前模块依赖，不重复添加：

- JUnit：JUnit 4，使用 `org.junit.Test/Before/After/Assert`。
- Mockito：使用 `org.mockito.Mockito`、`ArgumentMatchers`、`@Mock`、`@InjectMocks`、`ArgumentCaptor`。
- 不引入 JUnit 5、MockK、PowerMock 或 Mockito 新扩展，除非模块已有迁移约定。
- 优先使用 `dftest` 已提供的 JUnit/Mockito 依赖，尽量不新引入测试依赖；只有解析失败或明确存在版本冲突时才补充，并与当前模块保持一致。

## 2. 测试类型

默认写纯单元测试：

- 不启动 Spring，不使用 `@SpringBootTest`。
- 不访问数据库、Redis、Nacos、文件、HTTP、Feign、MQ 或真实第三方服务。
- 外部依赖 Mock；实体、DTO、值对象、集合直接构造。
- 测试可单独运行、重复运行，不依赖时间、随机数、环境和执行顺序。

需要验证 Spring MVC、Bean 装配、JSON、JPA 或真实 SQL 时，单独写切片/集成测试，并使用明确后缀：`*WebTest`、`*IntegrationTest`。

## 3. 目录和命名

- 测试目录：`<module>/src/test/java`。
- 包路径与生产代码一致。
- 类名：被测类名 + `Test`，例如 `YaoPinZdServiceImplTest`。
- 方法名：`方法_场景_预期`，例如 `load_existingId_returnsData`。
- 不使用 `test1`、`normalTest` 等无意义名称。

## 4. 编写规则

1. 先明确输入、返回值、异常、副作用和边界。
2. 按 Given/When/Then 组织测试。
3. 覆盖有意义的正常、边界、空值、异常和副作用场景。
4. 断言完整业务结果、错误码或关键消息；不要只断言非空。
5. 测试必须直接调用生产代码，不能复制一份实现进行断言。
6. 复杂逻辑优先提取为职责单一的包级方法；生产路径必须调用该方法，不要为测试扩大 `public` API。
7. 固定时间和时区；日期使用 `yyyy`，分钟使用 `mm`，不要使用当前时间。
8. 修改静态参数、请求上下文或全局状态后，在 `@After` 恢复。

## 5. Mockito 规则

- 只 Mock 外部协作者：Repository、Feign API、消息发送器、时钟、文件客户端等。
- 不 Mock 被测类；确需替换同类副作用时谨慎使用 `spy`。
- 只定义当前用例需要的 Stub。
- 保存、删除、发送等副作用用 `verify` 验证参数和次数。
- 禁止调用用 `never()` 或 `verifyNoInteractions` 验证。
- 复杂参数使用 `ArgumentCaptor`；具体值优先用 `eq()`，少用宽泛 `any()`。
- 只有顺序是业务契约时才验证顺序。
- 不用 `verifyNoMoreInteractions` 过度锁定实现细节。

JUnit 4 + Mockito 示例：

```java
@RunWith(MockitoJUnitRunner.class)
public class ExampleServiceTest {
    @Mock
    private ExampleRepository repository;

    @InjectMocks
    private ExampleService service;

    @Test
    public void load_existingId_returnsData() {
        when(repository.findById("id-1")).thenReturn(data());

        Example result = service.load("id-1");

        assertEquals("id-1", result.getId());
        verify(repository).findById("id-1");
    }
}
```

使用 `@Mock/@InjectMocks` 时必须配置 `MockitoJUnitRunner` 或其他 JUnit 4 初始化方式。

## 6. 分层边界

- Controller 纯单测：实例化 Controller、Mock Service，测参数转换、短路、返回值和异常释放。
- Controller 映射、校验、JSON、HTTP 状态码：使用 `MockMvc` 切片测试。
- Service：测业务分支、规则、编排和依赖交互。
- Repository 纯单测：测 QueryDSL/动态 SQL 条件、参数传递、结果转换；固定 SQL 和时间断言。
- PostgreSQL 执行、表字段、索引、JPA、事务和约束：使用数据库集成测试。

## 7. 执行

优先使用项目 Wrapper；无 Wrapper 时使用兼容的 `gradle`：

```powershell
.\gradlew.bat :<module>:test --tests "<package>.<TestClass>"
.\gradlew.bat :<module>:test
```

开发时运行单类；提交前运行模块全部测试。失败时定位首个根因，不靠重复运行掩盖不稳定。

## 8. 提交检查

- [ ] 模块级 `build.gradle` 已检查并按需添加 `dftest`。
- [ ] JUnit/Mockito 与当前模块版本一致，未混用 JUnit 4/5。
- [ ] 类、包、方法命名符合规范。
- [ ] 覆盖真实风险：正常、边界、空值、异常、副作用。
- [ ] 无 Spring/外部资源依赖，或已明确标为切片/集成测试。
- [ ] Mock 仅用于外部依赖，关键交互已验证。
- [ ] 断言有业务意义，测试直接调用生产逻辑。
- [ ] 测试独立、可重复，已运行相关测试和模块全部测试。
