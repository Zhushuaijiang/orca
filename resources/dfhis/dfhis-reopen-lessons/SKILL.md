# DFHIS 需求重打开经验教训

本文件只放索引与使用规则；每条教训的完整根因/错误做法/正确做法在 `docs/` 下按需阅读，避免 SKILL.md 随教训增多而膨胀。

- 通用流程教训（SQL/流转/恢复/回归定位类）→ `docs/process-lessons.md`
- HIS 业务口径教训（组件/控件/表结构/导出/三方对接类）→ `docs/business-lessons.md`

## 使用规则

- 交付前先过一遍下面的索引标题，命中相关主题的条目必须去读对应 doc 正文再动手或交付，不能只按标题臆测。
- 新增教训：正文写进对应 doc 文件末尾，本文件索引只加一行；description 触发词同步补充。
- 单一来源：一条教训只在一个 doc 里出现一次，其他技能用一行指针引用。

## 通用流程教训索引（docs/process-lessons.md）

1. SQL 附件必须与最终交付一致
2. 测试反馈逐条闭环
3. "待发布后验证"要主动跟踪
4. 重打开交付后负责人/参与人服从显式流转口径
5. 增量推送默认保留已确认负责人
6. 跨会话/跨天恢复在途需求前先重拉云效最新评论
7. 费用类生产 bug 先 diff 好/坏版本锁定回归提交，禁止表象兜底（洛宁重复计费）
8. HIS 改动必须同步单元测试，零测试交付一律不合格（AI 扫描判不合格）
