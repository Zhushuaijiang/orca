# mcp-aepd 提示词与会话审计结论

本结论来自 2026-08-26 的完整只读导出。原始数据包含内部信息与潜在敏感数据，不随技能分发。

## 数据范围

- 管理平台 PostgreSQL 事件：201 条，时间范围 2026-08-11 至 2026-08-26
- 底层 SQLite 会话：117 个；消息：6401 条
- 去重后的 system prompt：31 个版本
- 管理事件中正常业务答案 193 条，显式 TimeoutError 8 条
- 另发现 4 条 HTTP 429 错误文本被记录为 `ok`，说明数据库成功标志不足以代表业务回答成功

## 有效做法

- 147/193 条答案出现证据、依据、源码或路径等证据标记。
- 52/193 条答案主动声明未验证项或证据边界。
- 66/193 条答案包含建议、排查步骤或下一步。
- 191 条经过 Schema guard 的事件全部标记为有效，仅 1 条发生重试，无降级。
- 高质量答案普遍采用“结论先行 → 真实代码/Schema 证据 → 业务含义 → 排查或实施动作”。

应保留：意图路由、证据优先、Schema 守门、事实/推断分层、影响入口穷举、结论优先和可执行闭环。

## 主要失效模式

1. 上下文过载：事件的 prompt token 中位数约 14.4 万，P95 约 217 万；耗时中位数约 87 秒，P95 约 529 秒。复杂 Schema/代码问题贡献了大部分超时。
2. 提示词自相矛盾：一处要求“少上下文、精准触发”，另一处要求技能只要部分相关也全部加载，实际放大了工具调用和上下文。
3. 内部过程泄露：多条答案以“现在我已获取所有证据”“让我整理”“证据已经足够”等开场，少数还暴露技能/profile 搜索过程。
4. 非自包含答案：至少一条复杂问题只返回“用上面的 SQL”，但最终答案中没有所引用 SQL。
5. 错误假成功：4 条 429 被保存为 `ok`；显式 TimeoutError 也未提供部分证据或恢复策略。
6. 格式不服从：部分用户明确要求简洁，回答仍超过数千字符。
7. 动态配置硬编码：具体工具、路径、模型和分支策略被写进稳定提示词，换环境后容易失效或与仓库规则冲突。
8. 安全缺陷：长期记忆原文被注入 system prompt，其中出现真实访问凭据。技能中不得复述；应从提示词/记忆移除并按组织流程轮换。
9. 历史答案污染：旧答案和记忆中包含可快速过期的任务细节，容易被误当成当前证据。

## 对新技能的影响

- 稳定核心与环境适配、领域技能、当前证据分层，不复制整份 bot system prompt。
- 使用精确路由和证据清单代替“全技能、全库加载”。
- 失败状态根据实际回答内容和工具结果判定，不只信数据库 `ok`。
- 最终答案必须自包含、服从篇幅、移除内部过程话术。
- 把秘密扫描、假成功、悬空引用和路径可复制性纳入静态检查。
- 仓库与发布规则交给目标环境的 `AGENTS.md` 和专项技能，不在共享指南中写死。
