# 自动任务路由

在「设置 → 辅助模型」开启「自动路由编码任务」，为“任务分类”配置快速模型，
然后设置简单、常规、复杂任务的 agent、模型和推理强度，点击保存。

所有 Orca 管理的编码智能体使用同一协议。主智能体收到需求后调用分类模型，
Orca 按任务及难度选择已保存的路线：分析类返回辅助结果，文件修改类启动受监督的
worker，结果由主智能体审阅并汇总。主会话自身的模型不会自动切换。

## 配置优先级

先应用现有默认、任务、主智能体专用配置，再覆盖所选难度中明确指定的字段。
空的难度配置沿用任务设置；切换 agent 不继承原 agent 的模型 ID。
模型和推理强度只读取当前执行主机的条目，不借用本机、其他 WSL 或 SSH 主机的配置。

复杂任务默认由当前主智能体处理。关闭「复杂任务保留主智能体」后，可以为它配置
其他强模型；已配置复杂路线时，未显式选择保留主智能体则使用该路线。

分类置信度低于 0.65、路线未配置、辅助 agent 被停用或分类失败时，主智能体保留任务。
文本生成可按配置回退到原任务模型；可能已写入文件的 worker 不会因失败自动重跑。

## 自动触发

- Orca 原生聊天的用户消息和 `agent.launch` 的启动提示包含统一的自动路由指令。
- 桌面及 headless 运行时启动后，将版本匹配的 `orca-auto-routing` 发现技能安装到
  通用技能目录及已知的各智能体技能目录，保留用户自己的修改。
- 终端内直接输入的消息由主智能体遵循该技能发起路由，Orca 不解析终端按键。
  缓存技能目录的智能体需重启一次；技能是否被执行取决于智能体的遵循能力。
- 当前已有受监督 worker 的消息、其他智能体的消息和辅助结果不再路由，防止递归委派。

「试运行自动路由」使用已保存的配置，仅运行分类并显示决策。
「自动路由决策记录」显示当前工作区的最近 100 条决策，记录在协调端当前配置档案中。
文件修改进度、权威状态、收尾和输出档案沿用 Orca 编排；执行主机仍拥有这些事实。

## CLI

```text
orca auxiliary route --primary-agent codex --prompt "分析这份错误日志" --json
orca auxiliary auto --primary-agent kimi --prompt-file request.txt --json
orca auxiliary history --worktree current --json
```

`auto` 的输入应包含真正的用户要求以及执行所需的上下文。`route` 只分类和选模型。
`auto` 对分析任务返回结果，对文件修改任务返回既有 `worker-start` 回执。
主智能体按版本匹配的 `orchestration` 技能监督回执中的 Task/Dispatch，验收后汇总；
收到可能已启动或状态不明的回执时先检查，不能重复派发或抢写相同文件。

主智能体可以拆出独立子任务后分别路由，但必须监督全部结果，避免同时修改同一文件。
任务分类不会扩大用户授权，问题只授权分析；审批、发布和消息发送继续使用已有规则。

## 边界与验证

分类器只输出任务枚举、难度、原因和置信度，不能指定任意命令或模型。
辅助 agent 和模型来自设置。决策记录不复制原始请求全文。
辅助执行带 `ORCA_AUXILIARY_REQUEST=1`，自己的自动路由请求会被忽略。
写入任务复用原有编排的所有权、启动回执、权限和混合版本检查。
SSH 不可达不会转到本机；旧运行时需要更新后才能使用新增路由 RPC。

本功能提供跨模型委派，不能接管各 CLI 内部的上下文压缩、工具审批、子智能体或模型切换。
路由指令和技能属于智能体协作协议，不是对所有终端智能体逐条消息的强制拦截器。
